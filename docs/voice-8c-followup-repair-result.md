# 真人测试反馈修复：播放归属与8秒追问间隔

2026-10-07，分支 `codex/voice-8c-task6-7-10`。按用户“开始修复，完成播放后触发追问的间隔设置为8s”施工。仓库现有v6任务书、架构文档、效果图和next-env原有修改不纳入本次提交，不覆盖。

## 问题与实现

自查时本机有两个大屏连接。旧实现接受任意screen的当前轮播放回报；其中一个失败会取消另一个正在播放的答案，并立即播追问。真实日志有6条记录，其中5条播放终态全部failed，1条未进入答案播放。记录缺少失败原因，不能补写或断定历史失败一定来自浏览器自动播放限制。

- 在线大屏通过鉴权后的直接hello取得本连接screenId。HTTP唤醒必须携带该id；编排核验在线screen，将发起唤醒的大屏设为当前会话所属大屏。文字对话台发起会话时选择第一个在线screen。
- 仅所属大屏播音、开麦；其他标签只显示。正常答案、固定唤醒/追问的回报、Esc、聆听活动及录音上传都校验归属。所属连接断开立即取消会话；新连接取得新id，旧请求失效。
- **正常答案实际播完→保留答案8秒→触发追问**。8秒期间不显示追问、不开麦。语音会话播完追问提示后，等待输出延迟+300ms、麦克风真正打开，再开始原有3秒静默聆听窗口。
- 问候、没听清仍重新聆听；告别播完退场，不附加追问。插问、Esc、断线取消待触发的8秒计时；重复播完回报不重置计时。
- 整轮失败/超时不再播追问。卡片至少保留8秒，并保证长答案剩余打字时间+2秒，随后error退场。固定唤醒/追问失败或超时直接异常退场，不能假装播完、打开麦克风。
- 前端异常兜底仅退场，文字/无音频模式也由编排推进，不自行提前进入followup。点击页面可解锁后续音频，失败轮退场后再唤醒。
- 记录失败原因、所属大屏、播放结束耗时、屏幕数量和8秒间隔。固定提示失败写编排日志，不记录令牌。

- 原自查临时探针再次执行：第二个screen的failed或drained不再取消答案、不触发followup，第一屏保持answering。结果保存 `/tmp/voice-followup-probe-fixed.json`。
- 双标签浏览器验证使用真实hub、HTTP鉴权/CORS、Chromium AudioContext与确定性PCM，核对服务端记录的实际播完时间到state.change(followup)至少8000ms；其他标签没有排程音频。
