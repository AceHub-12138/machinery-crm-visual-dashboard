# 下一轮施工清单（待架构审核，未实施）

本轮没有产品补丁。所有后续方案须与性能报告最终证据一起审核；不得以“统一GSAP”为由跨过4K诊断或改写已验证业务状态机。性能目标区分：满档视觉效果、自动保护行为、真实展厅设备三种验收。

本轮已核实默认headless shell是软件后端。下一轮先把性能基准的GPU后端、显示刷新率和引擎帧率上限显式记录/分组，再决定产品renderer是否需要修改；不能把软件路径的失败直接换算为真实GPU优化需求。

## quality策略候选规格（不是已验证参数）

现有规则已经有45→52 FPS的阈值间隔，以及5秒降档/10秒恢复窗口。问题不是“没有任何滞回”；它缺少满档恢复后的失败记忆和分阶段容量验证。建议下一轮从以下最小策略实验开始：

1. 不改变业务状态机的INTRO/PULSE/voice优先级；抽出质量状态 `normal / low / probing`，保持对外等级与原渲染语义兼容。
2. low至少驻留一段时间（例如30秒，**候选值待对照确定**）；恢复仅在可见、无语音、无数字/共振突发且连续稳定窗口达标时进入短期probe。
3. probe恢复完整视觉路径，在若干连续窗口验证容量；不能因为低档轻负载60FPS就直接确认高档可承受。probe失败立即回低档，下一次探测间隔增加（如30/60/120秒，上限与负载恢复时效由架构审核决定）。
4. 如果绘制优化后满档持续达标，策略无需频繁介入；如果环境仍承载不了满档，诚实报告满档未通过并继续保护，不将“降档后稳定”包装成视觉验收。
5. 单测必须覆盖44/46/51/53阈值邻近、持续低/恢复、短突发、暂停原因叠加、forcedLow/reduced互相作用、采样窗口跨切换和日志上限。测试的是策略边界与因果序列，不是镜像实现。

## 视觉保护与替代路径

- 粒子保留150颗与原轨迹/尺寸/亮度。候选：同样Canvas绘制的局部dirty region、双缓冲/离屏纹理路径、同样视觉的专用合成层；必须先测像素/运动差异和GPU/内存成本，不直接加will-change或改WebGL。
- SVG地图、投影、城市优先标签、三层地图、mask、全国缩略图及交互保持。若Trace指向SVG raster，可评估静态底图缓存+独立动态覆盖层，保留相同矢量边界与标签清晰度；纹理化会有4K缩放清晰度/显存风险，须架构人审。
- 不把关闭mask/filter/Canvas的诊断对照直接做成正式优化。它们只证明某渲染路径的成本关联；替代技术必须保留视觉效果并单独验证。
- 数字、业务金额、语音答案共用既有确定性数据；视觉动画不能改变最终值或口径。

## 建议下一轮的拆分方式

先补测试工具的后端/刷新率/帧率上限核验与分组，再实施P0-B策略最小补丁；P0-A须满足软件回退需求或真实GPU仍失败的条件。每项独立开关、独立提交，先验实际性能与视觉，再讨论GSAP推广。P1-A是共享架构前置，不能夹带在全平台迁移中。最终具体热点和证据强度以 [4K诊断](03-performance-diagnosis.md) 与 [内存诊断](04-memory-diagnosis.md) 为准。

本轮完成后停止，交架构审核；本文件不构成推送、合并、部署、启动Task11或跨模块全面重构的授权。
