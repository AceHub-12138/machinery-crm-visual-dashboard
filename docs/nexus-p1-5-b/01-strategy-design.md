# P1.5-B 更新频率与候选质量策略

基线：P1.5-A `957ff26b3202510316213dec93f8a0d98c0758b4`。本轮候选策略仅通过 `debug=1&qualityExperiment=external` 隔离启用；默认入口仍执行 P1.4 原策略，默认动画引擎仍为 Legacy。

## 有效目标更新率

`effectiveTargetHz = min(场景空白页校准 RAF 参考频率, 引擎配置上限)`。

- Legacy native：上限取场景校准 RAF。
- Legacy/GSAP 相同目标实验：测试调度器上限 60Hz。
- GSAP native：产品 PoC 仍有 `gsap.ticker.fps(60)`，因此即使 Metal 底层 RAF 约 100Hz，有效目标仍为 60Hz。
- 目标不会根据已经卡顿的当前更新率下调；20Hz 异常不会被重新定义成“100% 完成”。

RAF 只叫浏览器调度代理，不叫真实显示 FPS。GSAP ticker listener 仍按当前一条待执行 Director job/每次 listener 的拓扑，从 Director 更新频率作 1:1 估计；没有伪装成独立直接遥测。

## 候选降档条件

候选同时保留一般低频证据和严重低频快速保护：

| 条件 | 候选值 | 作用 |
| --- | ---: | --- |
| 完成比例 | `< 75%` | 相对有效目标，而不是固定假设 60Hz |
| 绝对下限 | `< 45Hz` | 防止低刷新目标掩盖不可接受的绝对频率 |
| P95 尾部 | `> 1.8 × 目标间隔` | 避免平均值掩盖 50ms 尖峰 |
| 一般连续时间 | 4 秒 | 三项同时成立才降档 |
| 严重完成比例 | `< 55%` | 快速保护支路 |
| 严重绝对频率 | `< 30Hz` | 连续 2 秒进入低档 |

数据依据：无头 SwiftShader 4K 正常负载约 20–21Hz、P95 约 50ms，应快速保护；同为有头的 SwiftShader 4K 约 45–51Hz且尾部明显较轻，不应仅因旧固定 45Hz 边界偶发穿越就反复降档。

## 恢复探测与退避

低档的高频不直接用于恢复。候选流程为：

1. 初次降档后等待 10 秒。
2. 临时恢复完整正常负载进行探测。
3. 探测需连续 3 个 1 秒窗口同时满足：`更新率 >= max(52Hz, 目标的 90%)`，且 `P95 <= 1.5 × 目标间隔`。
4. 任一探测窗口失败，立即回到低档。
5. 连续失败后的等待依次为 20、40、60 秒，之后封顶 60 秒；不会永久停止探测。
6. 连续 3 个窗口通过后才进入正式 normal，失败计数清零。

这样会出现短时、目的明确的 `low → probe → low`，但不会把一次低档流畅误判为正式恢复，也不会形成原策略约 15 秒一轮的完整 `normal → low → normal` 振荡。

## 共振与暂停

- 低档拒绝共振的现有行为不变，只统计请求和拒绝原因。
- 页面隐藏、小川唤醒或 reduced motion 时，候选不累计低频证据。
- 恢复可见/退出语音/取消 reduced motion 后从新样本继续，不用暂停时间补算低频。
- 本轮没有修改共振时序、航线、粒子数量、视觉模块或静止终态。

## 回退

删除 URL 中 `qualityExperiment=external` 即回到原自动策略。实验控制器不存在于默认产品路径；丢弃本分支即可完整撤回。
