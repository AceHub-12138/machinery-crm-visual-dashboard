# P1.5-C 架构输入与风险清单

## 建议结论

候选策略具备进入 P1.5-C 架构设计的证据，但**不建议在 P1.5-B 直接替换正式默认策略**。建议先实现受版本控制的本地实验开关和可回滚灰度，完成真实展厅/目标浏览器长时间验收后再决定默认启用。

本轮数据不支持全面 GSAP 迁移。相同 60Hz 目标下 GSAP 没有表现出确定的性能优势；Metal 100Hz 环境中它仍受 ticker 60Hz 上限约束。

## P1.5-C 需要定稿的架构

1. **目标频率所有权**：由单一 MotionDirector 计算 `min(浏览器校准参考, 引擎上限)`；显示器切换、刷新率变化和后台恢复后应重新校准，不能把卡顿样本用于下调目标。
2. **策略状态机**：显式区分 normal、low、probe；probe 不是正式恢复。切换原因、证据窗口、失败次数、下一次探测时间必须可导出。
3. **ticker 直接计数**：若 GSAP 增加第二个消费者，当前“ticker listener 与 Director 1:1”的估计立即失效。正式架构应增加获批的只读 ticker listener 计数器。
4. **退避生命周期**：页面隐藏、小川唤醒和 reduced motion 时冻结证据窗口；恢复时避免把暂停时间计入退避或低频持续时间。是否保留失败计数需明确。
5. **正常负载探测体验**：探测会短时恢复完整动效，可能被人眼看到。正式版本需评估探测开始/失败的视觉过渡，不能以删除视觉模块或永久低档规避。
6. **多消费者 GSAP ticker**：`ticker.fps()` 是模块级共享设置。统一 GSAP 前必须定义所有权，禁止任一组件私自改全局频率或 sleep。

## 风险清单

- 阈值来自一台 M1 Ultra、Chromium 153 和有限场景；不能直接视为所有展厅硬件通用值。
- 有头/无头本身显著改变 SwiftShader 4K 结果；CI headless 不能替代现场浏览器验收。
- 100Hz 上用 RAF 离散节拍逼近 60Hz会产生 10/20ms 组合，P95 不能套用理想 16.7ms 单点阈值。
- 正常负载探测如果与共振、入场、语音退出同窗，可能把瞬时业务动效误判为长期能力；正式状态机需定义互斥或延后规则。
- 按 viewport 降低负载只用于证明恢复路径，不是生产质量策略建议。
- 长时间 JS 堆必须结合 GC、DOM、监听器、active timer 和实例数判断；原始堆正斜率不能单独定性泄漏。
- 候选外部控制器当前依赖调试按钮，正式实现不能通过 DOM 点击驱动，必须进入类型化策略接口并补齐单元/浏览器测试。

## 共振简化建议（仅提案）

若未来低档需要保留“业务已响应”的核心感知，可评估一次性地图整体亮度脉冲或静态重点路线高亮，不启动全量分段波纹/粒子增强。但这会改变默认视觉表现，必须由产品与视觉审核单独批准；P1.5-B 保持现有低档拒绝逻辑。

## 建议灰度顺序

1. P1.5-C 在实验参数下实现类型化策略状态机和直接计数器。
2. 本机软件/Metal 回归与 30 分钟以上长稳。
3. 目标展厅设备、实际分辨率/刷新率的人眼与资源验收。
4. 只在明确回退开关下小范围启用。
5. 数据证明优于旧策略后，再讨论默认切换；GSAP 架构统一另立审批。
