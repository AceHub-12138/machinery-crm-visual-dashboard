# 大屏设计规范（Rev 5）

面向 1920×1080 等比缩放的大屏。目标观看条件：**55–86 吋屏，4–8 m 视距**。
本文是这套大屏的单一事实来源：改样式先改令牌，不要在组件里写魔法值。

> **Rev 5 变更**：视觉方向调整为「高端展厅驾驶舱」—— 保留深色金属底、微网格、
> 冷暖双光、发光航线和动态节点，把科技感集中在地图与状态反馈；面板减少满屏描边、
> 大阴影和重复读数。地图新增交付态势标题栏，回款区改成「回款率 + 已收/未收 +
> 累计合同」的一眼闭环，交付预警按逾期优先排序。

> **Rev 4 变更**：字号标尺终于真的生效了（Tailwind 把「text + 方括号任意值 +
> 字号令牌」当成颜色，65 处字号一直在静默失效，详见第 2 节）；地图视口改为按中国
> 本土居中；底条从 84 提到 112，列宽按内容重新配平。版面仍是 2 行 × 3 列，
> 行高 838 / 112，列宽 360 / 880 / 1fr(624)。

> **Rev 3 变更**：地图去掉立体挤出，改为平地图 + 边缘光 + 球面光环；
> 底部「最近跟进」换成不含客户信息的「交付里程碑」；
> 右列换成「合同与回款」（大圆环 + 两条弧形进度条）；配色扩到六个语义色。

## 1. 三条硬约束

前两版之所以「不好看」，根因不是配色，而是下面三件事。任何改动都不得破坏它们：

1. **面板之间绝不允许重叠、也不允许悄悄裁掉内容。**
   每个面板 `overflow: hidden`，高度由**实测内容**反推，不是拍脑袋的固定值。
   第一版 `grid-rows-[300px_…]` 给了目标环面板 300px，而内容需要 396px，
   多出来的「缺口」卡片被下面的面板压住 96px——打开页面就能看见。
   Rev 3 重排时又踩了一次：CSS 自动排列把面板推出了画面。
   现在**每个格子都显式写 `col-start` / `row-start`**，并且有
   `src/lib/layout.test.ts` 做算术守卫。

2. **首屏必须有内容。**
   数据在 **Server Component** 里取好直接进 HTML。
   第一版是静态预渲染 + 客户端 `useEffect` fetch，首屏只有一行
   `COMMAND DECK LOADING`，展厅每次刷新都要先黑屏几秒。

3. **字号下限 18px。**
   第一版有 13 种字号、93 处 ≤11px 文本。按 55 吋屏 / 4 m 视距折算，
   11px 只有约 2.9 mm 字高，远低于可读下限；而最关键的
   「月度目标 / 达成 85.7%」恰恰是 10px。

## 2. 字号标尺

只有 7 级，全部 ≥18px。组件一律用 `text-label` 这类**工具类**，不要写
`text-[13px]`，也不要写「text + 方括号任意值 + 字号令牌」那种写法（见下面的坑）。

| 令牌 | Tailwind 工具类 | 值 | 用途 |
|---|---|---|---|
| `--fs-display` | `text-display` | 56px / 900 | （暂未使用，留给全屏级读数） |
| `--fs-hero-lg` | `text-hero-lg` | 50px / 900 | 本期合同额（KpiRail 主卡） |
| `--fs-hero` | `text-hero` | 44px / 900 | 回款率中心数字 |
| `--fs-brand` | `text-brand` | 32px / 700 | 头部字标「经营指挥舱」 |
| `--fs-metric` | `text-metric` | 28px / 900 | 各 KPI 数值、状态计数 |
| `--fs-brand-sm` | `text-brand-sm` | 24px / 700 | 头部 DC 徽标 |
| `--fs-label` | `text-label` | 22px / 700 | 面板标题、卡片主标签 |
| `--fs-caption` | `text-caption` | 20px / 400–500 | 列表行主文本、次级标签 |
| `--fs-micro` | `text-micro` | 18px / 400–500 | 辅助说明、图例、日期、单位 |
| `--fs-kicker` | `text-kicker` | 14px | **仅**头部英文装饰字（跟踪 0.34em） |

换算依据：55 吋屏 × 4 m 视距下 1px ≈ 0.28 mm，故 **18px ≈ 5.1 mm**（可读下限）、
**28px ≈ 8 mm**（舒适）、**50px ≈ 14 mm**（远处可抓取）。
屏更大或视距更远时，整套标尺按同比例放大即可。

### ⚠️ 2.1 为什么不能用「text + 方括号任意值 + 字号令牌」

Tailwind 4 处理 `text-[…]` 任意值时，要判断里面是**字号**还是**颜色**；
它看不出 CSS 变量的类型，于是**一律当颜色**，生成的是

```css
.text-\[var\(--fs-label\)\] { color: var(--fs-label); }   /* 字号根本没落地 */
```

后果极其隐蔽：整屏 65 处字号声明**全部静默失效**，文字退回继承值（16px 起，
环心那个手写的 46px）。表面看「版面没崩」，实际上是字号本来就没生效，而
「累计回款率」环心的 26.5% 就是这么压住进度弧的。

**修法与规矩**：

1. 字号令牌注册进 Tailwind 的 `--text-*` 命名空间（`globals.css` 的
   `@theme inline` 块），`@theme inline` 让工具类直接引用 `var(--fs-*)`，
   `:root` 仍是唯一真源，不复制值；
2. 组件里只写 `text-label` / `text-micro` 这类真实工具类；
3. `src/lib/font-scale.test.ts` 守卫：不许再出现那种任意值写法、每个令牌都
   必须注册、组件里不许有裸 `text-[22px]`。

### ⚠️ 2.2 任何被扫描的文件里都不要写出完整的坏类名

Tailwind 的候选扫描器**连注释和 Markdown 一起扫**（默认扫整个项目，`docs/`
和 `.review/` 都在范围内）。任何地方写下一个带 `*` 的非法候选，都会让整个
CSS 编译失败，而报错位置指向 `.css` 文件，极难定位：

```
./src/app/globals.css: Parsing CSS source code failed
Unexpected token Delim('*')
```

真实踩坑记录（同一个坑踩了三次）：先是 `globals.css` 的注释，然后是守卫
测试里的正则字面量，最后是本文档和 `.review/diag-fs.mjs`。

**规矩**：描述这个坑时一律写「text + 方括号任意值 + 字号令牌」这种文字说法，
或者用拼接构造（`"text-[" + "var(--fs-"`），不要写出完整类名。

**清缓存**：这类错误修好后 Turbopack 仍可能用旧缓存
（`.next/dev/cache/turbopack/*.sst` 里存着旧候选），需要删掉该缓存目录再重启
dev server。另外 `pnpm build` 会覆写 `.next/`，正在跑的 dev server 需要重启。

### ⚠️ 2.3 金额不许折行

「¥1,286.0万」这种读数一旦折行，卡片高度立刻失控。所以：

- `.money` / `.nowrap-num`：`white-space: nowrap`；
- KpiRail 四宫格里的金额用 `text-label`（22px）而不是 `text-metric`（28px）——
  158px 的卡片放不下 28px 的「¥2,072.0万」，硬撑只会断成两行；
- 主卡 50px：292px 可用宽实测 263px，刚好一行。

数字统一加 `.num`（`font-weight: 900` + `tabular-nums` + 极小字距），
避免滚动动画时宽度抖动导致重排。

## 3. 颜色

### 3.1 语义色：一色一义，六个色相统一明度

| 令牌 | 值 | 含义 |
|---|---|---|
| `--c-contract` | `#ee7d2c` | 合同额 / 品牌 / 目标（= 平台 `--brand-orange`） |
| `--c-collect` | `#45d8ee` | 回款 / 地理流动 |
| `--c-received` | `#46d39a` | 已收 / 已完成（比 `--c-live` 柔一档，用于大面积色块） |
| `--c-pending` | `#e8a33d` | 未收 / 待办 / 进行中 |
| `--c-growth` | `#8f8bf0` | 新增 / 线索 / 增长（唯一冷紫，专门区分「增量」语义） |
| `--c-overdue` | `#f2555a` | 逾期 / 风险 |

六个色相在暗底上的感知亮度接近，同时出现也不会互相抢。
**不再使用**旧版的 `gold #facc15`：它在暗底上与品牌橙几乎无法区分。

### 3.2 底色与表面

暖中性，不是纯蓝黑。

| 令牌 | 值 |
|---|---|
| `--stage-0` / `--stage-1` | `#05070c` / `#090d14` |
| `--panel` | `rgba(15, 20, 29, 0.9)` |
| `--panel-raise` | `rgba(24, 31, 43, 0.66)` |
| `--panel-border` / `--hairline` | `rgba(150, 168, 196, 0.14)` / `0.12` |

### 3.3 文字：对比度全部 ≥4.5:1

| 令牌 | 值 | 对 `--stage-1` 的对比度 |
|---|---|---|
| `--ink` | `#eef3fb` | ≈17:1 |
| `--ink-2` | `#b6c2d4` | ≈9.6:1 |
| `--ink-3` | `#8a94a6` | ≈5.8:1 |
| `--ink-4` | `#5d6779` | ≈3.0:1（仅装饰，不承载文字） |

旧版的 `#66758c` 只有 **4.13:1**，不达 AA，已弃用。

### 3.4 地图用色

- **中国省级高度色阶**：`--heat-0`（无数据 `#16202f`）→ `--heat-5`（最高 `#ffa451`），
  `heatIndex()` 分 6 档，图例带 0 → max 刻度。
- **邻国**：按视觉远近三档 `--c-neighbor-0/1/2`，越远越暗。
- **中国边界**：暖色外发光 + 青色亮芯两层描边，是全图最强的一条线。
- 顶面光照用**中性灰**（`terrain-light`），不要用橙色——否则会把数据色阶带偏。

## 4. 栅格

```
1920 × 1080
├─ HeaderBar                                    88px
└─ 行区 992px（padding 14，行间隙 14）
   行 = 838 | 112                 （112 是交付里程碑，Rev 4 从 84 提上来）
   列 = 360 | 880 | 1fr(624)，列间隙 14
```

| 区域 | 格子 | 内容 |
|---|---|---|
| 左列 | col 1, row 1 | 经营指标（KPI rail） |
| 中列 | col 2, row 1 | 发货地图（含左右各 150px 数据角标） |
| 右列 | col 3, row 1 | 上：累计回款率（441）／下：发货提醒（383） |
| 通栏 | col 1-3, row 2 | 交付里程碑（左侧摘要 210 + 右侧 5 张卡） |

**为什么是 3 列**：五块内容实测需要 558 + 490 + 690 + 122 + 168 ≈ 2028px，
而行区只有 1892px。硬塞的结果必然是某块被裁掉，所以只能分层。

**行高是怎么定的（Rev 4）**：

- 底条 112：`eyebrow 14 + 标题 26 + 统计 18 + 2×4 间距 + 上下留白` ≈ 74，
  再加面板 1px 边框。84px 那一版只装得下一行半（第三行会被压住）。
- 上行 838 全给三列。右列内部**按内容分配**而不是平摊：
  环要 `56头 + 36内边距 + 240环 + 16间距 + 25目标行 + 116进度条 ≈ 441`，
  提醒要 `56 + 36 + 3组×90 + 2×8 ≈ 383`，`441 + 383 + 14 = 838` 正好。
  ⚠️ 写成 `grid-rows-2`（等价于 `minmax(0,1fr)×2`）会让两块各拿 412，
  环不够、提醒富余 —— 环里那 26px 缺口就是这么来的。

**列宽是怎么定的**：地图面板宽度直接决定地图大小，所以中列最宽（880）。
KPI 列 360 是「标签不换行 + 50px 主读数一行」的实测下限。

改任何面板内容后，**必须**跑 `.review/audit.mjs` 重新实测（见第 11 节），
`src/lib/layout.test.ts` 只能守住栅格算术，守不住内容真实高度。

## 5. 地图：平面 + 边缘光 + 球面

### 5.1 数据来源

- 省界：`china-provinces-raw.json`（DataV 省界）
- 国界剪影：`china-raw.json`（DataV adcode 100000，**国家级合并轮廓**）
- 邻国：`ne-countries-raw.json`
- 三者由 `scripts/build-china-map.mjs` 用**同一套投影参数**写入 `china-map.json`，
  所以省界、剪影、经纬网严格重合。

> ⚠️ 不要试图用「抵消相邻省界」来还原国界。各省是独立简化的，
> 共享边界的顶点并不重合——实测 3331 条边只抵消掉 2 条，剩下的全是噪声。

### 5.2 画布不要留多余边距

`spanX / spanY` 要贴着陆地占用的经纬范围给。第一版 `spanX=1000` 而陆地只占 ~830，
viewBox 里 17% 是空白，渲染时整张图被等比缩小，地图看着比面板小一圈。
`src/lib/geo.test.ts` 有一条断言守着「陆地 ≥ 画布宽度的 78%」。

### 5.2.1 地图要按**中国本土**居中，而不是按画布中心

画布 1204×924（宽高比 1.303），面板可用区 866×852（≈1.016）。SVG 用
`preserveAspectRatio="xMidYMid meet"`，于是只渲染成 866×664 贴在中间，
上下各留约 94px。

问题在于画布的纬度窗口（-2.5°~63.5°，中心 30.5°N）是**为了给球面光环留位置**
选的，并不等于中国本土的纬度中心（36.3°N）—— 两者在画布上差了 75px。
结果：画布中心落在面板正中，中国本土却整体偏下。实测中国包围盒中心比面板
中心低 **28.5px**，肉眼看就是「地图没居中」。

解法在 `globals.css` 的 `.map-svg`：把视口纵向放大到 `866 × 924/1204 ≈ 915.6`，
再整体上移 `34.5px`（= 28.5 上移 + 6 内缩）。这样**仍由宽度定标**，缩放系数
与原来完全一致（0.719，中国一秒都不会被缩小）。

⚠️ 两个坑：

1. **height 必须写死**。带 viewBox 的 SVG 是替换元素，浏览器把
   `aspect-ratio = 1204/924` 应用到元素盒上，只给 `top/left/right` 就能定出
   高度 —— 写 `bottom` 不会拉伸，元素按宽高比算出 664.6px 就停住了
   （这正是第一次改没生效的原因）。
2. 数字与栅格绑死（地图格 880×866、内缩 6px）。改列宽/行高要重算，
   `src/lib/layout.test.ts` 有一条算术守卫：中国本土中心与面板中心偏差 ≤2px，
   并且会反证「不加上移量时偏差 >20px」。

### 5.3 球面感由三样东西叠出来

1. **经纬网**：留在地理坐标系里生成，再由统一投影落图，所以弧线一定与轮廓对齐。
   纬线每 10°、经线每 10°，30°/40° 与 110° 加粗作强调。
2. **同心光环**：圆心取 **viewBox 中心**（不是陆地中心，否则会缩成一小圈），
   半径 1.14 → 2.2 逐级放大、逐级变淡，最内圈带发光。
3. **球面明暗**：一个以 viewBox 中心为心的椭圆径向渐变，左上受光、右下入暗。
   **必须用椭圆**——用矩形会在画面上留下一块硬边深色方块。

### 5.4 中国边缘光

三层描边叠出来，而不是一条硬边：

| 层 | 作用 |
|---|---|
| 暖色外发光 | `--c-contract`，`feGaussianBlur(7)` 后叠两次，让光「溢出来」 |
| 青色亮芯 | `--c-collect` + `#b8f4ff`，1.8px 模糊 + 1.1px 实线 |

### 5.5 标签防重叠

`placeLabels()` 给每个标签试 8 个方向，取第一个不与已放置标签相交的位置，放不下就丢弃。

- **优先级：城市 > 省名 > 邻国**。城市名丢了就不知道圆点在哪儿；邻国名丢了不影响读图。
- **包围盒用行高而不是字号**（`0.88 + 0.32` × size）。用字号估会低估近 30%，
  京/津、皖/苏这种紧邻的省名就会叠在一起。
- **同级排序**：先放有数据的省，再按经度从西到东——西部稀疏，先占位能给
  东部密集区留余量。

## 7. 两块「挤」出来的排版（Rev 5）

字号标尺真正生效后，18/20px 的正文比原来 16px 占宽约 25%，
两处必须显式做取舍，否则就是「裁掉」或「糊成一团」：

**回款率环（`.ring-box`）**

- 环只承担总体回款率，金额全部移到环外，避免同一图形里重复三次业务口径。
- `192×192` 固定正方形，右侧纵排已收款 / 未收款，底部再用一条分段进度条
  表达结构；441px 面板高度内没有重叠或裁切。
- 外圈刻度从 80 条降到 24 条，只提供仪表方向感。坐标统一保留 4 位小数，
  避免服务端与浏览器浮点尾差触发 hydration 告警。

**发货提醒（`ReminderRail`）**

- 面板只有 325px 高（右列 383 − 面板头 56 − 内边距 36）。
- 每组 2 条 + **两列并排**：3 组 × 90px + 2×8 = 286px，余 39px。
  竖排 3 条要 401px，实测第三行被 `overflow-hidden` 裁掉 24px（旧版就这样）。
- 每条只有 272px 而三个字段需要 ~315px，**必然放不下**，所以两个字段都
  `truncate`，公司名给 `basis-28` 先截断（公司名信息密度低），设备名吃剩余。
  不给设备名 `flex-1`（basis 0）—— 那样公司名会贪掉全部剩余宽度，
  设备名被压到 60px 只剩「数控键…」，读起来像乱码。
- 组头计数是**全量**，所以「每组只列 2 条」不丢信息。

## 8. 动效预算

**同时运行的无限动画 ≤ 8 个。**

- 唯一允许的循环动画：`live-dot` 脉冲、`factory-core` 呼吸、航线 `flow-dash`。
- 航线错峰 **0.06s**：整屏读起来是一条呼吸节奏，而不是 12 条虚线各自乱跑。
- **数字滚动**只在数值**真的变化**时发生，并且用 `requestAnimationFrame`
  直接改写 DOM 文本，不走 React state——一屏十几个数字，每秒 60 次
  `setState` 是无意义的开销。
- 全部动效响应 `prefers-reduced-motion: reduce`。

## 9. 面板材质

统一为「顶部短光轨 + 面板头（56px）+ `overflow: hidden`」：

```css
.panel         { 低对比边框、深色金属渐变、轻量投影、overflow: hidden }
.panel::before { 顶部 76px 品牌橙短光轨 }
.panel-head    { 56px 高，底部 hairline }
```

地图是科技感主舞台：保留经纬网、球面环、发光边缘与动态航线；其他面板只做

## 10. 迁回平台时

1. `src/app/screen/sales/page.tsx` 是 Server Component，
   把 `buildMockScreenPayload()` 换成 `getCrmDashboard()` / `listSalesTargets()` 即可，
   **组件层零改动**（`ScreenCrmPayload` 的形状就是按平台接口对齐的）。
2. 权限：非 `SUPER_ADMIN` 账号拿不到全公司目标（接口侧 403 且会被静默过滤）。
   **展厅 kiosk 需要专用账号**，并且 `territories` 必须配好——否则所有 KPI 都是 0。
3. 地图：平台已改用 Leaflet + 天地图，需要 `TIANDITU_KEY`。
   本大屏用的是自带剪影的矢量方案，**不依赖任何密钥**，可以独立于天地图运行。
4. 平台没有引入任何图表库（recharts / echarts / antd 都没有），
   本大屏同样保持手写 SVG + Tailwind，不新增依赖。
5. 回款率口径：`已回 / (已回 + 未回)`。mock 数据里
   `totalPaidAmount + totalUnpaidAmount` 必须等于 `totalContractAmount`，
   否则大屏上的回款率会与「已回 / 待回」互相矛盾（这个坑踩过一次）。

## 11. 改动之后怎么验（不要靠肉眼）

静态守卫只有栅格算术，**内容真实高度必须用浏览器实测**。工具都在 `.review/`：

```bash
# 1) 起 dev server（端口 3115）与带 CDP 的 Chrome（端口 9333）
# 2) 逐面板实测：面板/内容高度、真实裁切、折行、字号直方图
node .review/audit.mjs "http://127.0.0.1:3115/screen/sales?fit=0" 9000 > .review/audit.json
node .review/report.mjs .review/audit.json

# 3) 单点几何（环盒、地图视口、卡片…）
node .review/probe.mjs "<url>" "@.review/sels.json"

# 4) 1:1 局部截图（先看整屏再看局部，局部容易骗自己）
node .review/crop.mjs "<url>" .review/crop.png 300 88 880 880
```

判读要点：

- `report.mjs` 的 **REAL clipping** 一栏才是真裁切。`leading-none` 会让
  `scrollHeight` 比 `clientHeight` 大 4~6px，这是行盒与字号相等造成的
  **假阳性**，不要照着它去调版面（脚本已把 `ch <= 20` 的单独归类）。
- **font histogram** 里每个字号都必须能在第 2 节的表里找到。
- 地图居中：跑 `.review/expr-map.js`，`offsetFromPanelCenter` 的 x/y 都应在 ±8px 内。
- 改完样式若报 CSS 解析错误而文件明明是对的，先删
  `.next/dev/cache/turbopack`（旧候选缓存）再重启 dev server。

## 13. 前端设计改造 P0（本节数值优先于前文历史版本）

施工基线 `6f484a0`；分支 `feat/screen-design-polish`。仅改前端展示，不改公开接口结构或语音编排服务。

- 舞台 1920×1080；栅格仍为 360 / 880 / 624，面板坐标未变。
- 主读数令牌 64px，FitText 最小 44px；回款环令牌 56px，最小 40px。缩字按最终值测量，容器 ResizeObserver 和字体就绪后重测。
- caption / micro 为 20 / 18 设计像素；1280×720 下补偿系数封顶 1.12。该补偿不是物理字高 18px 的保证；浏览器字号守卫检查缩放前的设计值。
- 语音标题 34px、副标题 22px、播报 24px（行高 1.5）、状态 20px、追问 22px，其余信息至少 20px。单位不缩到字号下限以下。
- 普通卡 700px，网格 64 / 270 / 170 / 52；简报 380px，网格 64 / 170 / 52。卡顶上移至 y=300，普通卡底边 1000，不放宽原有 1020×scale 边界。
- 有音频提示时，提示占卡片顶部专用空间，卡高最多 720px；无卡时提示位于转写区，不悬浮页面底部。
- 根节点和后代都响应减少动效。Canvas 每次状态/尺寸变化静态绘制后停止刷新；真实音频振幅保留 20Hz 采样，避免减少动效连带停止音频诊断。
- 无数据通过可选的展示原因明确表达；不会把金额为 0 误判成缺失数据。当前服务没有新增无数据自动判定逻辑，未提供该元数据时保持原来的会话状态标签。
- 文字截断提供悬停完整值和读屏全文；客户后缀清理、从中间省略、省份简称只作用于展示，不改原始数据或聚合键。
- 旧卡片高度断言保留并更新；读屏专用隐藏元素不算视觉溢出。新检测按 Range、字体墨迹与实际裁剪边界判断，并用故意溢出和面板交叠验证检测器。

浏览器截图与测量输出位于 `test-results/design-polish/`，历次回归 JSON 和失败 trace 保留于 `.review/design-polish/`。

P0 阶段最终验证：35 个测试文件 / 477 项单测通过；74 项浏览器回归通过，0 skipped / 0 flaky；Lint、构建通过。先前误报、音量采样回归及音频排程时钟边界失败均保留在 .review/design-polish，最终结果单独记录，不用旧失败覆盖最终结论。
