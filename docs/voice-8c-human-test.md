# Task 6 / 7 / 10 真人与展厅测试记录

## 本机开始测试

双击仓库根目录的 `启动本机语音测试.command`。它依次检查 LM Studio 分类模型、本地 ASR/TTS、语音编排、Next.js，并打开 Chrome 的 `http://localhost:3015/screen/sales?voiceLive=1`（另带本机 hub 地址和一次性鉴权片段）。允许麦克风，先点击页面一次，再说「你好，小川」或按 F9。

启动脚本复用健康服务，不下载模型，不卸载已有模型。缺少配置时停止并显示原因。模型、Python 和参考对路径沿用本机配置；日志在 `services/voice-orchestrator/logs/`。令牌存于 git 忽略的 `.env.local`，不打印到日志。当前使用 fixture 数据，是真语音服务加演示经营数据；不代表生产 CRM 验收。

这轮按用户最新选择保持 Mac 开机。以下项目需要用户本人说话和听音，自动注入录音的测试不能代填。

## 展厅记录工具

本批复审通过后，再进行展厅验收。使用正式麦克风、音箱和浏览器；跨机 HTTPS、令牌及 Origin 配置属于 Task 9，需先具备。观察脚本只订阅 console 事件，不发唤醒、提问或关闭指令，也不保存问题与回答原文。先打开大屏，再在仓库终端运行：

```sh
# 20 次正样本：每次等待回到常态且冷却结束再说，必要时增加 seconds
node --experimental-strip-types scripts/voice-field-record.mjs --mode positive --seconds 300
# 5 种词各 10 次，轮次间等退场和冷却
node --experimental-strip-types scripts/voice-field-record.mjs --mode negative --seconds 600
# 完整一小时背景音；期间不按 F9，不在对话台唤醒
node --experimental-strip-types scripts/voice-field-record.mjs --mode noise --seconds 3600
# 真人提问 / 连续 30 轮稳定性观察
node --experimental-strip-types scripts/voice-field-record.mjs --mode conversation --seconds 1800
```

JSON 保存到本机忽略的 logs，含唤醒时间、退场原因和匿名耗时，不含令牌。Ctrl+C 提前保存会标记 `complete=false`；不足 1 小时不推算误唤醒门槛。`playbackStartMs` 是上传后到 hub 收到浏览器首音回报的耗时，包含回传，不能当成物理麦克风说完到扬声器出声的 L2。唤醒词到真实出声 ≤ 0.8s 需现场计时或同步录制确认。
